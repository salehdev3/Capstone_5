# Human-reviewed data improvement v4

Run `notebooks/Phase2_Data_Review_V4.ipynb` on CPU. Existing dataset splits, reference files, checkpoints and measured results remain untouched. Outputs live in `CameraTrap_Phase2/data_review_v4/`.

1. Inventory all 14 species by crop count, distinct events and cameras in each split. Planning floor 100 training crops is a collection aid, not a guarantee. The original validation support ceiling is recorded without changing macro-F1 denominators.
2. Queue all 190 training/validation mask references, with 71 geometry-affected images first (73 polygon findings). The six documented training-only removals are reproduced with original/derived SHA checks. Geometry findings do not establish semantic label errors.
3. Interactive canvas: load original or an optional conservative geometry/raster-derived suggestion; drag vertices, shift-click to delete vertices, add/delete polygons. No model predictions or IoU-to-model ranking are shown. Inspect original visible animals. Every saved verified correction needs a reviewer name, observation and explicit completeness confirmation; malformed geometry is preserved as a draft rather than verified. Review history is append-only and saved after each image. Suggestions are never automatically ground truth.
4. Export a timestamped review ZIP containing records, source identities and reviewed labels. Completion status reports how many are actually verified. Original validation changes define a new development-reference version; they do not convert prior results into independent tests. Test masks are not opened by this workflow. No training is started or release installed automatically.
5. Optional public catalogue collection: find unused events from original training cameras for low-support species, cap 2 frames per event and 150 staged images. Other splits are never reassigned. Decode hashes and perceptual distance <=4 quarantine duplicates against all frozen images and accepted staged candidates. Team verification is required before data can enter any future training release. Original public annotations are not represented as new team reviews.

Local audited counts and conservative-suggestion statistics are in results/phase2/data_review_v4. The public storage endpoint returns 403 in the assistant environment; catalogue discovery/download must execute in Colab. The planner reports actual candidate availability there; no new class coverage is claimed before download and review. If catalogue cameras cannot supply missing assessment classes, additional licensed sources/new team camera locations are required. A new independently assessed dataset needs frozen camera/event splits before training.

Browser controls are tested in headless Chromium: panel rendering, iframe resize request, visible Save, required fields, vertex dragging and returned review data. Colab integration explicitly displays JavaScript and sets the output iframe height. Run one image per cell execution; the cell waits for your Save or Close click. Full live Colab interaction still requires running the notebook. No human review or new images have been invented. Manual semantic corrections and extra data are prerequisites for claiming completed data improvement.

A geometric warning can be an intentional zero-area bridge in a disconnected mask. If the original foreground is visually correct, a named reviewer may explicitly retain the unchanged topology with a written reason. The raster must remain exactly equal to the original; such exceptions are listed in the export status, not hidden as repaired geometry.

Automatic approval: SAM can return non-simple merged contour paths. Cached drafts with finite, bounded, nonempty masks for every expected animal can be reviewed without changing their rendered foreground. Approve explicitly records the disclosed geometry exception and source proposal; it does not certify simple polygon geometry or anatomical correctness. Missing masks remain blocked. The standalone approve_cell.py updates the helper without regenerating cached masks.
